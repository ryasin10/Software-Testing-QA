# 🎬 What is a Test Scenario?

## Overview
A **Test Scenario** is defined as any functionality or feature that can be tested. It represents a high-level classification of testing requirements and answers the fundamental question: **"What to test?"**

---

## 📊 Test Scenario vs Test Case

| Feature | Test Scenario | Test Case |
| :--- | :--- | :--- |
| **Focus** | High-level functionality (*What to test*) | Detailed execution steps (*How to test*) |
| **Detail Level** | Low detail, single-line statement | High detail with inputs, preconditions, and expected outputs |
| **Derivation** | Derived directly from Requirement Documents / User Stories | Derived from Test Scenarios |
| **Example** | Verify User Login Functionality | Step 1: Open Login page<br>Step 2: Enter valid user/pass<br>Step 3: Click Login<br>Expected: User redirected to Dashboard |

---

## 💡 Why Create Test Scenarios?
* **Ensures Complete Coverage:** Ensures every feature specified in requirements is accounted for.
* **Quick Approvals:** Allows stakeholders and product managers to review testing scope rapidly.
* **Effort Estimation:** Helps estimate QA resources, workload, and project timelines.

---

## 📝 How to Write Test Scenarios
1. **Read Requirement Documents:** Analyze BRS, SRS, and Use Cases thoroughly.
2. **Identify User Journeys:** Determine every possible action and workflow a user can take.
3. **Group Functionality:** Categorize scenarios based on system modules (e.g., Authentication, Payments, Search).
4. **Trace Requirements:** Map scenarios back to requirements to avoid missing functionality.
